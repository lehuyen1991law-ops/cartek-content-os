# End-to-end acceptance test — 2026-11-05

Phase 6 acceptance run of Cartek Content OS, performed by Claude Code. The test uses a clearly marked **test item, CTK-L-9001**, based on the real sheet idea **CTK-L-0015** "Lỗi P0300 - Ác Mộng của Mọi Động Cơ?" (`'Content Direction'!F12`), aimed at Vietnamese garage technicians.

**Rule of the test:** no research was fabricated to make anything pass. The brief, script skeleton and SEO package were written; the research was deliberately not performed, so every technical claim stays `unverified` and the gates must block.

## Result

The system behaved as specified. It created the workspace from the real idea, accepted a complete brief (G2 PASS), and then blocked or failed every gate whose evidence does not exist yet. It refused a release package and produced a schema-valid draft package that lists 31 blocking issues. No approval was possible: the item is a test item, its claims are unverified, and the required independent and human reviews are missing.

### What the run demonstrates

- A real sheet idea becomes a traceable workspace without inventing anything.
- The brief can be completed and passes; nothing else passes without evidence.
- Unverified claims, a missing Cartek 2 feature register entry, unfinished narration and missing assets are reported as BLOCKED, never as PASS.
- Safety topics are detected and must be flagged or dismissed; flagged topics demand a qualified human technical review before approval.
- A test item can never receive a release package; the draft package carries every blocking issue for the production team.

### Not covered by this run

- Approval, publication and performance review on real content: no real research or human sign-off exists yet. The full path (independent reviews, human sign-off, approval, release package, upload checklist, publication record, performance data, correction log, re-approval after a post-publish SEO change) is exercised with a synthetic fixture in a temporary sandbox by `tests/test_qc.py` (`TestCompleteFixture`, `TestLifecycle`).
- Live capture from the Google Sheet with `--fetch api` (no OAuth token in this environment). The import of the 2026-11-05 capture is covered.
- The test item's `seo.md` checklist predates the split into pre-approval and upload checklists made the same day; it was left unchanged so the recorded reviews keep matching the content.
