# CLAUDE.md — Cartek Content OS operating guide

Read this file first. It is the entrypoint for Claude Code and any compatible AI agent working in this repository. It tells you what Cartek is, which files are authoritative, which skills to use, and when you must stop.

## 1. What Cartek is

Cartek is an automotive diagnostic content brand. Its YouTube channel teaches OBD2 diagnostics, the **Cartek 2** diagnostic tool, automotive systems, common faults and practical garage troubleshooting. Content language is **Vietnamese**.

- Channel topic (sheet `'Content Direction'!B1`): "Chia sẻ kinh nghiệm sửa chữa ô tô qua hệ thống OBD2".
- Long-form target "5-8 phút"; Shorts target "< 60 giây". These come from the sheet and are starting requirements, not fixed laws: deviations need a recorded rationale.
- Brand line in every CTA: **Cartek - Check your car**.
- Strategy: [strategy/channel-positioning.md](strategy/channel-positioning.md), [strategy/content-pillars.md](strategy/content-pillars.md), [strategy/brand-voice.md](strategy/brand-voice.md).

## 3. Authoritative information (in this order)

1. **The Google Sheet** "Cartek: Youtube Release" is the planning source. It is **read-only** for this repository. Its raw capture lives in `data/source/`, its normalized form in `data/normalized/` ([data/README.md](data/README.md)). Never edit either by hand: re-run the import.
2. **Policy and vocabularies** in `config/` (workflow stages, QC policy, platform limits, taxonomy, production assumptions).
3. **Contracts** in `schemas/` (content record, production package, performance data, source data).
4. **Strategy** in `strategy/` (positioning, pillars, personas, competitors, editorial guidelines, brand voice, product facts).
5. **Cartek 2 capabilities** come ONLY from [data/reference/cartek-2-feature-register.yaml](data/reference/cartek-2-feature-register.yaml). It is currently empty: no Cartek 2 feature may be claimed as fact until the product team verifies it ([strategy/product-facts.md](strategy/product-facts.md)).

Generated, never hand-edited: `data/source/`, `data/normalized/`, `data/import-manifest.json`, `reports/import-report.md`, `reports/content-board.md`, `qc-report.md` files, `exports/`.

## 6. Producing a new content item

Example request: *"Create a Cartek long-form content package explaining P0300 for Vietnamese garage technicians."*

1. Find the idea: `python3 scripts/new_content.py --list-ideas --search p0300` → `CTK-L-0015` ("Lỗi P0300 - Ác Mộng của Mọi Động Cơ?", pillar P4, `'Content Direction'!F12`).
2. Create the workspace: `python3 scripts/new_content.py --from-idea CTK-L-0015 --audience technician --owner "<name>"`. If a workspace exists, continue it; never create a second one.
3. Research (skill **automotive-researcher**): register every technical statement as a claim with sources. `python3 scripts/set_status.py CTK-L-0015 --stage RESEARCH`.
4. Brief (skill **cartek-content-strategist**), then script (skill **youtube-scriptwriter**). Check timing with `python3 scripts/qc_content.py runtime CTK-L-0015`.
5. Technical review (skill **technical-fact-checker**), SEO (skill **youtube-seo-specialist**), storyboard and assets, moving the stage with `set_status.py` as each step finishes.
6. QC (skill **content-qc-inspector**): `python3 scripts/qc_content.py run CTK-L-0015`, then independent reviews recorded with `qc_content.py review`.
7. A human approves with `python3 scripts/qc_content.py approve CTK-L-0015 --by "<name>"`; this writes the release package.

Finish each work session with the checks in section 8 and report which gates are still FAIL or BLOCKED and why.

## 7. Technical accuracy (hard rules)

Full rules: [strategy/editorial-guidelines.md](strategy/editorial-guidelines.md) and [workflows/research.md](workflows/research.md).

- Distinguish OBD-II standardized functions from manufacturer-specific ones, confirmed facts from assumptions, a diagnostic trouble code from a confirmed root cause, and model-year/vehicle differences.
- Never invent diagnostic data, vehicle compatibility, fault causes, specifications or Cartek 2 features.
- Clearing a code never repairs the fault. Any mention of clearing codes says so.
- Every technical statement in a script is a claim in `item.yaml` with a source of an accepted type (`config/qc-policy.yaml` → `claim_source_requirements`). Insufficient evidence → keep it `unverified` (QC blocks technical approval) or remove it.
- Hazardous topics (high voltage, brakes, steering, airbags/SRS, fuel system, lifting, 12 V battery, hot/moving parts, ADAS) go in `safety.flags` and need a **qualified human** technical review, plus a spoken safety warning.
- Never fabricate YouTube metrics, and never promise CTR, ranking or views.

## 8. Validating a deliverable

```bash
python3 scripts/qc_content.py run <ID>        # gates G1-G8 -> <workspace>/qc-report.md
python3 scripts/qc_content.py status <ID>     # what approval still needs
python3 scripts/validate_content.py           # repository integrity
python3 scripts/export_package.py <ID> --draft   # production package preview
make check                                    # tests + import check + validate + links (as CI)
```

Gate results: PASS (criteria met with evidence), FAIL (a deliverable breaks a rule: fix it), BLOCKED (unfinished deliverable, missing evidence, or a pending sign-off). Report BLOCKED and FAIL honestly; never weaken a check or edit a test to make it pass.

## 9. Updating the repository safely

- Work on a branch; commit messages `content(CTK-L-0015): ...`, `strategy: ...`, `ops: ...` ([CONTRIBUTING.md](CONTRIBUTING.md)).
- Never write to the Google Sheet. Status changes are copied to the sheet by hand ([workflows/publishing.md](workflows/publishing.md)).
- Refresh sheet data only through `scripts/import_sheet.py` ([workflows/sheet-import.md](workflows/sheet-import.md)). It never touches `content/`.
- Change stages with `scripts/set_status.py` so history is recorded. Do not edit `reviews` or `history` by hand.
- After publishing: log factual corrections in `item.yaml` → `corrections`; changes to published metadata (title, thumbnail, description) need QC reviews and a re-approval ([workflows/publishing.md](workflows/publishing.md#corrections-after-publishing)).
- Never commit secrets (`.env`, tokens, service-account files) or raw video/audio. Link footage from `production.footage_links`.
- Do not delete or renumber IDs. Do not publish anything to YouTube.

## 10. When to block publishing

Stop and report instead of proceeding when any of these is true:

- An automated gate is FAIL or BLOCKED, or `qc_content.py status` shows an unmet requirement.
- A claim is `unverified` or `disputed`, a source is missing, or a Cartek 2 feature is not verified in the register.
- A safety-flagged item lacks a qualified human technical review.
- No human editorial sign-off on the current content, or the content changed after approval (fingerprint mismatch).
- The item is a test item (`CTK-?-9xxx`).
- The publish URL or date is not real and confirmed.
